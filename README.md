# 卡丘琴谱器 · strinova-piano-sheet

卡拉彼丘（Strinova）琴房用的**谱面播放器 + 制谱器**。

把琴谱放到一块置顶浮窗上，演奏时高亮"下一个该按哪个键"。
浮窗平时**鼠标穿透** —— 枪的准星直接打过去，不挡画面；
要自己弹的时候打开「可按」，浮窗就变成一台可以点的琴。

```
        ┌──────────────────────────┐
        │         小星星            │   ← 曲名行
        ├──────────────────────────┤
        │   5'      6'      7'  1'' │
        │  1'      2'      3'   4'  │   ← 4×4 键位，跟着谱面亮
        │   ◉5     4       7     8  │      ◉ = 当前该按的键
        │   1      2       3     4  │
        └──────────────────────────┘
         ⠿ │ ▶ │ ──────●─── │ 🔊 │ 跟打 │ 可按
```

---

## 先说清楚：它碰不碰游戏

**主程序（`main.py` + `core/` + `ui/`）只做三件事：**

* 显示一块自己的置顶窗口；
* 读你放在 `sheets/` 里的**纯文本**谱面文件；
* 播放时把"该按哪个键"画在这块窗口上。

**它不做的事：**

| | |
| --- | --- |
| 读游戏内存 | ✗ 不读 |
| 注入游戏进程 / 挂钩子 | ✗ 不注入 |
| 模拟键鼠输入 | ✗ 不模拟 |
| 修改任何游戏文件 | ✗ 不碰 |
| 截屏 | ✗ 主程序不截屏 |
| 联网 | ✗ 全程离线 |

唯一跟系统打交道的地方是 `core/winfocus.py`：它用
`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` **只查询**当前前台窗口
属于哪个进程（好知道游戏在不在前台），**不读那个进程的任何内存**。

> ⚠️ **`tools/` 目录是另一回事。**
> 那里是开发过程中的研究 / 调试脚本，其中有几个确实会抓屏
> （`grab_game.py`、`watch_motion_fast.py` …）或模拟鼠标
> （`debug_drag.py` …）。它们是**早期实验功能的残留**，
> **主程序一行都不调用，也不会被打包进 exe**。
> 那几个实验功能（屏幕跟随、听音识谱、自动贴合）已经整套删掉了 ——
> 见 `DEVELOPMENT.md` 的 §16.38。

> ⚠️ **风险自负。** 任何第三方程序与游戏同时运行都存在不确定性。
> 这个程序的设计目标就是"一个老老实实的置顶窗口"，但**用不用、怎么用，
> 请你自行判断**，作者不对账号安全作任何承诺。

## 功能

### 浮窗（演奏时看的那个）

* **置顶 + 鼠标穿透** —— 不抢焦点，准星直接穿过去
* 4×4 键位网格，跟游戏里的琴一一对应（标着 `PAD 1`～`PAD 16`）
* 演奏时：
  * 当前该按的键 —— 亮色高亮 + **收缩的圆圈**（圈缩到中心就是该按的时机）
  * 下一个音 —— 淡黄预告；连按同一个键 —— 角落显示 `×2` `×3`
  * 按下去的瞬间闪一下
* 顶上一条把手：拖动挪位置，还带着播放 / 暂停、进度条、曲名
* **「跟打」** —— 播放时**不放原声**，改成你自己点格子出声。
  练琴用：听着自己弹的，才听得出来哪儿按错了。
* **「可按」** —— 浮窗变成一台能点的琴，点哪个格子出哪个音。
  开着的时候鼠标**不再穿透**（这是 Windows 的限制：没法只让"格子那块"
  接收鼠标），所以它是个临时状态，用完记得关掉。
  这时浮窗只显示空键位，谱面提示会收起来 —— 你是自己弹，不需要提示。

### 控制台

* 曲谱列表（`sheets/` 里所有 `.txt`）+ 刷新 / 打开文件夹 / 删除
* 播放：速度、倒计时、循环、播放声音
* 显示：不透明度、标签、底板
* 浮窗位置与大小
* 全局热键

### 制谱器

* 时间轴编辑：拖、框选、多选、复制粘贴、撤销重做
* 打击垫试听，写完按红线位置插进去
* 导入 / 导出文本谱面

## 跑起来

需要 **Python 3.10+**（开发用的是 3.14）。

```bash
pip install -r requirements.txt
python main.py
```

只要两个依赖：`PyQt6`、`numpy`。

> 音源是**运行时合成**的（`core/synth.py`），不需要额外的音频文件。

### 打包成 exe

```bash
python -m PyInstaller --noconfirm --clean "卡丘琴谱器.spec"
```

产物在 `dist/卡丘琴谱器/`，整个文件夹一起拷走就能用。

> 收尾时 PyInstaller 偶尔报一句 `PermissionError` 然后 exit code 1 ——
> 那是它在重试写 exe 尾部，**只要 `dist/` 出来了就是成功**，
> 看日志最后一行 `Build complete!`。

## 谱面格式

纯文本，一行一个乐句。语法**完全兼容
[StrinovaPracticeRoom](https://github.com/)（猫弹琴 2.8.0）**，
现成的曲谱可以直接用。

```
小星星
#100#
1 1 5 5 6 6 5-
4 4 3 3 2 2 1-
```

| 写法 | 意思 |
| --- | --- |
| `1`～`7` | 中音 |
| `#4` | 半音 |
| `6.` | 低音 |
| `3'` | 高音 |
| `1''` | 倍高音 |
| `-` | 每个 `-` 加 1 拍（`1-` = 2 拍；单写 `-` 是休止 1 拍） |
| `^` | 每个 `^` 乘 0.5（`^1` = 0.5 拍，`^^1` = 0.25 拍） |
| `&` | 和弦，同时发声：`1'&3'&5'` |
| `#数字#` | 变速，如 `#156#`，在任意位置实时改 BPM |
| 空格 / 换行 | 只是排版，会被跳过 |
| `~` | 延音记号，不影响时长 |

「不像乐谱的文字」会被整段跳过，而且**不当作休止**（不留空档）——
所以标题、注释可以随便写在谱子里。

## 开发

```bash
python -m pytest tests -q
```

`DEVELOPMENT.md` 是这个项目最值钱的东西：它按轮次记着**每一个坑的
根因和证据**，包括好几处"看起来对、其实是假的"的诊断。
改代码之前建议先在那儿搜一下关键词。

里面几条反复踩到的教训，摘在这儿：

* **`QApplication.widgetAt()` + `QTest.mouseClick()` 永远测不出"能不能点"** ——
  前者不看 Windows 的 `WS_EX_TRANSPARENT`，后者直接给 widget 送事件、
  绕过整条消息路径。要测这个只能用 `WindowFromPoint` + `SendInput`。
* **顶层窗口的 `WA_TransparentForMouseEvents` 是单向门** ——
  Qt 在窗口创建那一刻就把它固化成内部状态，之后再 `setAttribute(False)`
  也回不来，而 `testAttribute()` 还会骗你说已经是 `False`。
  鼠标穿透只用 `WS_EX_TRANSPARENT`。
* **Qt 的 QSS 里 `padding` 会吃掉小按钮的内容区** ——
  28×22 的按钮配上 `padding: 5px 14px`，内容区宽度会变成 **−2 px**，
  文字一个都画不出来。小按钮必须单独把 `padding` 归零。
* **别用 emoji 当图标**（`📚 ▶ ⏸ 🗑`）—— 真机上会被字体替换成彩色方块
  或者干脆不显示。这个项目的图标全是运行时自己画的 PNG
  （见 `ui/appstyle.py`）。
